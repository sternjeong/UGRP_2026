5.0 데이터 원칙확정

팀이 실제로 확보 가능한 데이터는 인터넷에 이미 공개된 정형/텍스트 데이터뿐이다. 설문 등 별도 수집 캠페인 불가, 재학생 개인 수강기록 같은 비공개 학사 데이터 접근 불가.

  • MVP 기능은 전부 공개 데이터(실라버스·권장이수체계도·연구실 키워드/논문)만으로 구현 가능해야 함
  • 축B "학생 수강 이력"은 제품 출시 후 자사 사용자의 opt-in 1st-party 데이터만을 가리킴 — 제3자 스크래핑/설문 아님
  • 부수 효과: IRB 등 개인정보 수집 절차 불필요 → "프라이버시-바이-디자인" 서사로 활용

  5. (보조 참고정보) 온톨로지 기반 전형적 경로 제시 확정 · 07-22

    실제 "동료들이 걸은 길"이 아니라, 권장이수체계도+온톨로지 그래프(hasPrerequisite 체인, 이수구분 가중치)에서 도출한 "이 관심사라면 논리적으로 자연스러운 전형적 순서"를 보여준다. 개인 수강기록이 필요 없어 §5.0과 정합적이며 1개월차 데이터로 바로 구현 가능.

    이전 초안 "동료 궤적 비교"(재학생 실제 수강경로 익명화)는 폐기됨 — 필요한 데이터(제3자 학생의 실제 수강기록)를 팀이 합법적으로 확보할 방법이 없다는 게 §5.0 정리 과정에서 드러나 되돌림.

기술 아키텍처

핵심 관점: 학생의 연구 방향성은 시간에 따라 진화하는 상태(state), 매 학기 수강 선택은 그 상태에 가하는 제어입력, 관측 가능한 건 노이즈 낀 신호(수강 과목, 관심 키워드)뿐이다. 통신/제어/신호처리/딥러닝/강화학습 배경이 하나의 시스템으로 통합된다.

축 A — 상태 표현 학습 (Deep Learning)

현재 최우선 축

기성 SBERT 그대로 쓰지 않고 도메인 특화 임베딩을 직접 학습(연구 실적화 목적).

학습 신호: PREREQUISITE 필드는 결측 90%로 미채택. 대신 (a) 권장이수체계도 순서, (b) 이수구분+과목코드 기반 레벨 신호, (c) 연구실 키워드-과목 어휘 중첩, (d) 팀 라벨링 소규모 골드셋(평가 전용)을 positive pair 소스로 사용.

Supervision 보강확정 · 07-22
  • 가중 결합: (a)~(c)를 신호별 신뢰도로 확률적 결합 (Snorkel류 weak-supervision aggregation 검토) — (a) 고신뢰, (c) 저신뢰로 차등
  • Hard negative mining: "같은 학과·비슷한 레벨이지만 그래프상 미연결" 과목을 negative로 구성
  • PU-learning 주의: 미관찰 쌍을 곧바로 negative로 취급하지 않음 — 평가 프로토콜에도 동일 적용
  • 과목코드 피처화 확장: 레벨 신호를 과목코드 숫자 패턴까지 세밀화

근거: Liang et al. AAAI'17 · Pan et al. ACL'17 · 최신 대체 참고 — "A Bayesian approach to inferring prerequisite structures and topic difficulty" (BEA 2025)

모델 확정 · 08-03: 백본은 BGE-m3(다국어, 8192 토큰 긴 컨텍스트, dense/sparse/multi-vector 하이브리드)로 확정. 이 위에 MultipleNegativesRankingLoss 등 contrastive fine-tuning. 여유 시 얕은 GAT/GraphSAGE로 그래프 구조(선수과목 체인) 명시 반영. 2024~25 참고: "Toward General and Robust LLM-enhanced Text-attributed Graph Learning"(2025), "GraphRAG-Induced Dual Knowledge Structure Graphs for Personalized Learning Path Recommendation"(2025)

베이스라인: 옵션3(온톨로지+앵커문장) 구현 시 OWL2Vec4OA(2024.12, OWL2Vec* 후속작)를 평가 baseline으로 추가. 확정

평가: (1) 권장이수그래프 엣지 hide 후 링크예측 비교, (2) text-only vs text+graph ablation, (3) 골드셋/소규모 학생 휴먼평가(NDCG@k, Precision@k)

축 B — 상태 추적 (Signal Processing)

학생의 수강 이력을 시계열 신호로 보고, 노이즈 낀 관측(수강 과목, 자기보고 키워드)으로부터 잠재 연구방향 상태를 추정. 칼만 필터 또는 지수가중 이동평균 후보. 최근 관심 변화를 과거 이력에 덜 휘둘리며 반영하는 게 목적.

축 C — 경로 계획 (Control / RL)

스트레치 목표

테크트리 생성 기능의 알고리즘 백엔드. 목표 임베딩까지 상태를 유도하는 문제를 유한구간 MPC 또는 선수과목 DAG 위 MCTS 플래닝으로 정식화. 선수과목 순서·학점 상한·잔여 학기는 하드 제약.

알고리즘 최종 선택(MPC vs MCTS) 미정

offline RL 검토 후 기각확정 · 07-22

"Doubly Constrained Offline RL for Learning Path Recommendation", "Privileged Knowledge State Distillation for RL-based Educational Path Recommendation"(KDD 2024) 등 최신 offline RL 계열은 "상호작용 로그가 적을 때 RL 하는 법"을 다뤄 이 축의 제약과 정면으로 관련 있으나, 클로즈베타 이전 로그 데이터가 사실상 0이라 학습이 어려울 것으로 판단해 planning(MCTS/MPC) 우선 결정 유지.

참고: "On Conceptualisation and Overview of Learning Path Recommender Systems in e-Learning" (2024 서베이)

학습 목적 포함

9개 전체 확정 · 07-23

스키마 초안 — 클래스: Course Lab Professor ResearchTopic(계층형) Skill Department · 관계: hasPrerequisite(transitive) isSubfieldOf(transitive) partOfDepartment coversTopic specializesIn requiresSkill hasSynergyWith(non-transitive, §7.2)

깊이 설계 원칙: transitive 체인이 충분히 깊어야 "LLM beam search는 얕고 우리는 깊이 무관하게 완전하다"는 어필이 성립한다. 예시(통신 서브도메인, depth 5):

ElectricalEngineering→ Communications→ InformationTheory→ SemanticCommunication→ JointSourceChannelCoding
근접 선행연구 대비 차별점확정 · 07-23

Abu-Rasheed et al., "LLM-Assisted Knowledge Graph Completion for Curriculum and Domain Modelling in Personalized Higher Education Recommendations" (arXiv 2501.12300, 2025) — 문제의식(커리큘럼/도메인 모델링 + 개인화 고등교육 추천 KG)이 축D와 거의 동일한 선행연구.

  • 이 논문: LLM이 그래프 완성(completion)을 직접 담당, 평가는 그래프 구조 지표 + 전문가 정성 피드백에 그침(formal reasoner 검증 없음). 스케일도 임베디드시스템/FPGA 2개 모듈에 국한.
  • 우리: OWL 2 DL + reasoner(HermiT/Pellet) 논리적 일관성 검증 + 링크예측 정량평가(축A 평가 프로토콜과 동일 방법론) + EECE 전체·타학과 융합 스케일.

툴스택: Protégé(저작) + HermiT/Pellet(reasoner) + Neo4j(런타임 materialize) 확정 보류 — 스키마가 더 무르익은 뒤 재검토(§11)

§7.2

hasSynergyWith — 명시적 선수과목 밖의 "시너지" 관계

신설 · 07-23
문제 — 실데이터로 확인된 사례

EECE233(신호및시스템)의 교과목 개요 텍스트에는 선수과목 언급이 전혀 없다. 반면 EECE301/306/308/309/320 등 8개 과목은 "선수과목 : 신호및시스템"이라고 명시해, EECE233을 가리키는 edge는 많지만 EECE233 자신이 무엇에 기반하는지는 텍스트만으로 전혀 드러나지 않는다.

그런데 전자전기공학과의 "5. 학년/학기별 전공과목 일람표"(§5.1)를 보면 MATH203(응용선형대수)이 EECE233 바로 앞 학기, 같은 전공필수 슬롯에 공식 배치되어 있다 — 자유서술 선수과목 필드가 잡지 못하는 관계가, 로드맵 표의 학기 위치에는 존재한다.

MATH203 응용선형대수→ EECE233 신호및시스템

2학년 1학기 전공필수(MATH203) → 2학년 2학기 전공필수(EECE233), 학과 로드맵 표에서만 확인되는 인접 배치

관계 정의: hasSynergyWith(A, B) — A를 먼저/함께 이수하면 B의 학습에 실질적으로 도움되지만, B 수강의 필수조건은 아님. hasPrerequisite와 의도적으로 분리(방향성 결정, 07-23):

관계성격축C 경로계획주 용도
hasPrerequisite텍스트 명시, transitive하드 제약CQ#1/#2 최소 선수과목 체인·이수 가능 여부
hasSynergyWith로드맵 공동배치 등에서 추론, non-transitive소프트 가점(하드 제약 아님)추천 랭킹·근거 설명(축E)
두 관계를 하나로 합치면 CQ#1의 "최소 선수과목 체인"에 선택 과목까지 섞여 들어가 축C 하드 제약 계산이 오염된다는 것이 분리의 핵심 근거.

추출 방법

  • 1차(고신뢰): §5.1에서 구분한 "학년/학기별 전공과목 일람표"를 학과별로 파싱해 (학과, 학년, 학기, 이수구분, 학수번호) 튜플화. 같은 학과 로드맵 내 더 이른 (학년,학기) 슬롯의 과목 → 더 늦은 슬롯의 과목으로 후보 edge 생성(학기 거리가 멀수록 confidence 감쇠). hasPrerequisite로 이미 확정된 쌍은 제외해 중복 표현 방지.
  • 2차(저신뢰, 로드맵 밖 순수 타학과 시너지용): §7 축A에서 이미 결정한 개념 단위 접근 재사용 — Liang et al. AAAI'17 / Pan et al. ACL'17 스타일 concept-level dependency mining. 과목 개요에서 후보 개념구를 추출해 "어느 과목이 그 개념을 정의/도입하는가"를 앵커로, 다른 과목이 그 개념을 정의 없이 응용만 하면 정의 과목 → 응용 과목 방향으로 후보 생성. 두 신호는 축A와 동일한 "가중 결합" 원칙으로 합친다.

축A와의 관계: 학년/학기별 로드맵 데이터는 축A 지도학습 신호 (a)(권장이수체계도의 순서 관계)와 동일한 원천을 공유한다 — 축A는 이를 임베딩 학습용 연속 신뢰도 신호로, 축D는 이산적 OWL object property로 사용한다는 점이 다르다. 로드맵 표 파싱 파이프라인은 축A/축D 공용 인프라로 1회만 구축하면 된다.

§7.4

타학과 시너지 신호의 구조적 한계와 보강 후보

신설 · 08-03
문제 진단

학과 권장이수체계도는 학과 내부 과목끼리의 순서만 기록하는 문서라서, 타학과 과목쌍은 (a) 신호 관점에서 사실상 전량 unlabeled다. 이는 §7 축A의 "PU-learning 주의"(미관찰 ≠ 관계 없음) 수준을 넘어, 특정 범주(타학과 쌍) 전체가 구조적으로 라벨 신호 자체가 없는 상황이다. 이대로 학습하면 모델이 "타학과 과목은 다 무관하다"는 편향을 학습할 위험이 있다.

대응 후보 검토중 · 미채택

  1. 개념 단위 마이닝(§7.2 2차방법) — 이미 메인 대응책으로 결정됨
  2. 연구실 키워드-과목 어휘중첩 신호 (c)를 학과 경계 없이 전역 적용
  3. 소규모 사람 라벨링 시드 + 임베딩 유사도 기반 확산
  4. Hard negative mining 시 타학과 쌍을 negative 후보군에서 제외/저가중 — "타학과=무관" 편향이 negative sampling을 통해 재유입되는 것을 차단
  5. 평가를 학과내부 쌍 / 타학과 쌍으로 분리 리포트 — 근본 해결은 아니지만 최소 비용으로 문제를 가시화
신규 후보 신호 (e) 과목명 표면 유사도

구현 비용은 매우 낮음(문자열/임베딩 유사도로 즉시 계산 가능). 단, "동치 관계"(사실상 같은 과목의 이중개설)와 "시너지 관계"를 혼동할 위험이 있고, 신호 자체는 방향성(정의→응용)을 주지 못하므로 (b) 과목코드 레벨 신호와 결합해 방향을 정해야 함.

태그 vs 온톨로지 전략 비교

결론 · 07-22

원래 기획서의 "Custom Tag Score Vector"(태그별 앵커문장 → 문서 유사도 스코어링)와, 이후 도입한 formal 온톨로지 ResearchTopic 계층의 관계를 정리한 논의.

옵션 1 — 태그만 유지

장점구현 단순, dense 임베딩과 자연 결합, 태그 추가 쉬움
단점태그 간 관계 없어 깊은 추론 서사와 단절, 두 체계 정합성 문제

옵션 2 — 온톨로지만

장점체계 단순화, 다단계 추론 깊이 어필과 완전 일치
단점자유서술 텍스트의 미묘한 의미차 못 잡음, 커버리지 갭 취약

옵션 3 — 결합 채택

장점연속 스코어링 + 깊은 추론을 모두 확보, 두 근거 동시 제시 가능
단점설계/유지 복잡도 최고 — 노드-앵커문장 동기화 부담
결론(2026-07-22): 옵션 3 풀스케일 채택. ResearchTopic 계층 전체에 앵커문장을 부착하고, 노드 추가/수정 시 앵커문장 동기화를 온톨로지 편집 워크플로우의 필수 단계로 취급한다.
